## Gitとworktreeの継続運用（全アプリ共通）
アプリの作業を始める前に、対象リポジトリの AGENTS.md（ある場合）とGit状態（branch / HEAD / status / worktree / upstream）を実物で確認する。正式な開発起点・採用済み成果を確認せず、main・公開用リポジトリ・日付が新しいブランチを正本と推定しない。

同じ機能・同じ修正の継続作業では、原則として既存の開発ブランチとworktreeを再利用する。「前回を壊さないため」という理由だけで毎回新しいブランチを作らない。並行作業・大きな実験・独立検証など隔離が必要な場合に限り、新規ブランチを作る。その際は分岐の必要性、起点コミット、統合先、終了・片付け条件を記録する。作業中の他担当のworktreeは変更しない。

作業完了時には未コミット変更・未追跡ファイル・成果物と一時生成物を分類して整理し、必要なものをコミットまたは別途保存する。必要と確認できていないファイル、未統合ブランチ、worktreeを削除しない。Git状態が未整理なら完了ではなく「保留」と報告し、branch・commit・Git状態・統合先・残課題を明記する。

A18ではまず `C:\Users\User\source\repos\web-tools-preview\docs\DEVELOPMENT_GIT_POLICY.md` を具体的な運用ルールとして参照する。A18は開発ソース、Web公開、素材プレビューが別リポジトリであり、プレビュー公開を正式採用と混同しない。

現時点では自動CI/フックによるGit検査は導入しない。手動での運用を見て必要に応じて検討する。
