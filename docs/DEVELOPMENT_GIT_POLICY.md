# A18「とっておき美術館」固有のGit運用補足（2026-10-26）

この文書は**全アプリ共通のGit戦略ではない**。共通の整理原則は同じPC内の `C:\Users\User\source\repos\GIT_WORKFLOW_COMMON.md` に置く。対象リポジトリの既存の仕様や開発手順を優先する。

## 管理境界
- `web-tools-preview`：ゲーム実装を含む開発リポジトリ。A18用の複数worktreeが紐づく。
- `a18-totteoki-museum-pages`：Web試遊・公開リポジトリ。開発ソースの最新正本とは限らない。
- `a18-art-previews`：美術素材比較プレビュー公開リポジトリ。表示・公開したことは正式採用やゲームへの統合を意味しない。

## 作業起点と分岐
- `main` や日付の新しいbranchを正式な最新実装と決めつけず、前回監修で承認された成果・関連コミット・現在のworktree状態を確認する。
- **同じ目的の修正を別チャットで継続するだけなら、すでにある安全な作業branch/worktreeの利用を優先検討する**。他担当が進行中の作業を勝手に再利用しない。
- 新しい機能、独立QA、並行素材制作など別の作業単位は、必要に応じて独立ブランチにする。新規に作った場合は起点と統合先、採用判定を残す。
- 現時点でA18全体の最新正式起点を、この文書のみを根拠として決めない。統合対象は実物照合で判断する。

## 作業完了
- ソース、試作品、承認済み素材、Pages公開物の採用関係を区別して報告する。
- 作業後にtracked/untracked、不要な検証スクリプト・画像・ログを分類して整理し、成果を保存・コミットする。破壊的削除や未承認の統合を行わない。
- branch、HEAD、Git状態、必要なPush・公開検証、統合先・残課題を明記する。作業中のworktreeを一括で削除しない。

## 除外
自動CI／Gitフック、過去の全worktree一括整理は今回の対象外。
