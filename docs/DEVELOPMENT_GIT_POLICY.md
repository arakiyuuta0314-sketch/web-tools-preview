# A18 Git開発運用ルール（試行版 v1 / 2026-10-26）

## 適用範囲
A18「とっておき美術館」の開発・素材作成・ブラウザ検証・公開連携。まずA18で試し、他アプリへの全面適用は運用実績を見て判断する。自動検査（CI／フック／自動削除）はまだ導入しない。

関連リポジトリ：
- `web-tools-preview`：A18のゲーム実装を含む開発リポジトリ。既存の多数のworktreeが共有するGit。
- `a18-totteoki-museum-pages`：A18 Web試遊／公開用の別リポジトリ。
- `a18-art-previews`（ローカル `a18-art-previews-publish`）：美術素材の比較・プレビュー公開用の別リポジトリ。

**正式な開発起点・採用済み素材・公開元は、リポジトリや `main` の名前だけで決めない。** 過去の検証結果と実ファイル、HEAD、依存・未統合差分を照合し、まだ確定していない場合は「未確定」と報告する。公開用リポジトリをゲームの正本と推定しない。

## 1. 作業開始
1. 対象リポジトリ・作業フォルダ、現在のブランチとHEAD、`git status --short --untracked-files=all`、`git worktree list`、remote／upstreamを確認する。
2. 前回の確定採用元と作業中ブランチを特定する。別作業が使用中のworktreeには書き込まない。
3. **同じ目的の通常修正では、既存の作業ブランチを継続利用する。** 各修正・各チャット単位で無条件に新しいブランチ／worktreeを作らない。
4. 既存ブランチが未コミット変更を含む場合は、内容を把握してから作業する。勝手に巻き戻さない。

## 2. 独立ブランチの例外
並列作業、破壊的な実験、正式版と同時に比較を保持する必要、重大な仕様分岐など、**実際に隔離の必要があるときだけ**作成する。作成時に理由、起点コミット、統合先、採用／破棄の判断方法を記録する。起点が不明なまま分岐を増やさない。作業中の他ブランチへ勝手にマージしない。

## 3. 実装・公開
- 安定状態はコミットで保持する。小修正ごとに新規ブランチを作ることをバックアップ代わりにしない。
- 実装、素材、検証成果物を分ける。試験用の画像・ログ・一時スクリプトは、原則リポジトリ外の作業領域に置く。
- `git add -A` や `git clean -fd` を安易に実行しない。追加・削除対象を確認する。
- `main` への通常の実装直書きは避ける。正式統合は、採用判定・差分確認後に明示した統合先へ行う。
- GitHub Pagesへの掲載、制作物の承認、ゲームの正式実装への統合は別工程として扱う。プレビュー公開成功だけで正式採用と判断しない。
- 公開・Pushが必要な場合は対象リポジトリ、branch、GitHub Pagesへの影響を事前に把握する。

## 4. 作業終了（手動の必須チェック）
1. `git status --porcelain --untracked-files=all` で追跡・未追跡変更を確認する。
2. 生成ファイルを「正式採用」「今後必要な証跡」「不要」に分類する。前二者はコミットかリポジトリ外へ保存し、後者は内容確認・必要なら退避後に削除する。
3. 作業をコミットし、必要なPush・反映を確認する。未採用・未統合ブランチの変更は勝手に消さない。
4. 開始ブランチ／終了ブランチ、HEAD、検証結果、Git状態、統合先・残課題を引き継ぎ報告に記載する。
5. worktreeの削除は、それが不要であり、未統合・未保存の成果を失わないと確認した後に限る。

**Gitに未処理の作業ファイルや説明できない差分があれば「完了」と宣言しない。** 理由・所有者・次の扱いを記録した「保留」扱いとする。 `reset --hard`、強制push、未確認のworktree／branch削除は禁止。

## 5. この試行期間にやらないこと
自動CIゲート、コミットフック、全既存worktreeの一括整理、過去の未統合ブランチの無断マージ／削除。運用を見て必要性を判断する。
