- assets/gallery_base.webp ：館長・作品写真を含まない第1展示室背景

## 検証上の制約
現在の背景は生成した素材シートの一部分を抽出・人物消去処理したもので、床や壁にわずかな修復跡が残っています。

元のA18 50作品機能版と新グラフィックv0.6比較版は維持しています。


## v0.8 検証仕様（2026-10-22）
- iPhoneのSafariアドレスバー・タブバーはWebページ自身から任意に消せない。対策として、デフォルトを「全体表示」に変更して、シーンを縦横比固定のまま縮小してすべて表示。任意で「拡大表示」に戻せる。
- manifest.webmanifest とiOSのホーム画面追加用メタ情報を追加。ホーム画面から開いた場合のスタンドアロン表示はiPhone実機で未検証。
- 館長の足元の当たり判定と、スタッフ・展示枠に近づいたときの会話・鑑賞可能判定を分離した。範囲外で「作品を調べる」「話しかける」は非表示。
- 入口の受付、壁、階段柵、展示室のソファ、ロープ、植物、彫像、壁への通り抜けを防ぐ当たり判定を追加。3額縁＋スタッフ＋扉への到達経路を自動探索で確認。
- 館長スプライトの透過余白を除いて足元の座標に合わせ、足元の影を縮小。4方向×5コマの画像を切り替える。切り抜き座標は事前計算済み（Canvas画像のピクセル読み出し不要）。
- 初回起動時に「美術館の名前」を入力。初期値は「パズル美術館」。ゲーム開始後も左上の名前から変更できる。館名だけブラウザlocalStorageに保存し、展示写真・作品のテストデータは更新するとリセットされる。
- 3展示枠に実際の写真を登録し、完成日不明・入れ替え・一覧・受付自動整列の機能は維持。
- 50作品版や旧v0.7のソース・素材は上書きしていない。製品向けのフルバージョンは別工程。


## v0.9 歩行・近接操作調整（2026-10-22）
- iPhone12 Safari実機スクリーンショット6枚で、館名入力・足元接地はOK、操作ボタンの表示は改善。ただし最接近時にボタンが消える、衝突判定が甘い箇所、歩行速度が遅いとの指摘。
- 歩行速度：旧9px/95ms ≒95px/秒から新12px/65ms ≒185px/秒へ変更（理論上約1.95倍、実機は未測定）。
- 高速歩行で当たり判定を飛び越えないよう、1回の移動12pxを3pxごとに分割判定。物体に接触すると停止。
- 作品/スタッフ/扉の判定を単純な幅狭の長方形から距離判定に変更し、接近時の表示範囲と離れるまでの維持範囲に差を設けて点滅・消失を抑制。
- 展示室初期座標を、額縁の前に少し歩いてからアクションを表示する位置へ変更。展示室手前左右の階段手すりエリアにも衝突領域を追加。
- 入口の受付/展示扉、展示室の3作品への経路探索合格。長押し490msで96px移動→ボタンを離すと停止、受付カウンター・中央ロープの最接近でもアクション維持、頭上持ち上げ/左額縁への交換、写真登録・完成日不明、縦向き回転案内をChromiumで自動テスト。
- 全体表示の縮小版と拡大表示の切替、館名の初回設定機能は従来通り。
- iPhone12 Safari実機のv0.9速度・衝突の体感確認は未実施。背景の見た目と固定の額縁・家具の完全分離は次の制作工程。


## v1.0 展示額縁とアクション判定の修正（2026-10-22）
iPhone12 Safari実機v0.9フィードバック：歩行速度は良好。近接操作がやや遠くから出る。額縁で写真を交換した後、前の写真の一部が左右に残ることを修正対象として優先。
- 根本原因：gallery_base.webpには、写真のプレースホルダー外周に元のサンプル画像の左右端が焼き付いており、Canvasが中央の小さい矩形だけ描画していた。
- assets/gallery_clean.png：金色の装飾枠は保ちつつ、3額縁の内側の元画像と古い紙片部分をすべて消去して無地の額装下地にしたロスレスPNG。
- 展示用矩形を額縁の内側と揃え直し、Canvasはその領域全体をクリップして、現在の登録写真だけをアスペクト比維持で描く。写真の登録/移動/交換後も古い画像が残らない設計。写真なしの枠は"+"を表示。
- アクション判定は展示枠 enter=38/leave=51（旧49/61）、受付 enter=43/leave=58、扉 enter=43/leave=57 に近づけた。ヒステリシスは維持して表示のちらつきを抑える。
- Chromium 844x390、932x430および縦390x844で、最初は近接ボタン非表示→近くで表示、頭上持ち上げ→隣へ入れ替え、新しいピンク画像への再登録、完成日不明をテスト。各段階のスクリーンショットを目視確認し、古い絵の左右残存なし。
- v0.5（50枠版）、v0.6、v0.7などは上書きしない。iPhone12 Safari v1.0実機検証は未実施。

## v1.2｜受付スタッフの新作登録と自動額装（2026-10-22）
- 受付スタッフへ話しかけると『新しい作品を預ける』『作品一覧』『自動並べ替え』が選べる。
- 受付スタッフの初回挨拶・作品への称賛・完成後の言葉は複数の台詞からランダム選択。直前と同じ定型文が連続しない調整。
- 新作写真を選んだ後、『自動で周囲の余白、明るさ、色味、コントラスト、鮮明さを整えてよいか』とスタッフが確認。
- 許可したときだけ写真の補正を試し、補正前と補正後を横並びで確認。トリム、明るさと色味の調整、細部の軽い強調は個別に切替可能。原本を選ぶことも可能。
- 補正内容は写真に合わせて保守的に推定（輝度分布、暗部・明部、ニュートラル色の色かぶり、コントラスト・彩度、細部の強調）。展示用コピーは長辺最大1800pxで、元写真そのものは保持する。
- トリム候補は外周のテクスチャ変化に基づく単純な推定。画像の75%以上を残す候補のみ表示し、85%以上なら初期選択（範囲は非破壊的）。被写体自動判別や正確な遠近補正ではないので誤検出があり得る。ユーザー確認必須。
- 額縁への自動サイズ調整は縦横比を保って写真全体を収める。鑑賞画面では『展示版』『元写真』を切り替えて細部を確認できる。
- 既に作品が飾ってある展示位置に上書きする場合は、既存作品が試作版の登録一覧からも失われる点を明示し、確認後にのみ入れ替える。
- 写真は外部サーバーへ送信せず、ユーザー端末のブラウザ内で処理。試作版はリロード時に作品データ消去（館名のみ保持）。
- Safari等での顔・手・キャラクターを生成して消すAI加工、ガラス表面の光反射を確実に除去する処理、傾斜/台形の精密な自動補正はまだ非対応。補正が逆効果なら原本を採用する。
- Chromium 844x390/932x430でスタッフ会話→写真提出→許可→自動補正→元画像比較→展示枠入替確認→登録→鑑賞で展示版/原本切替を検証。直接登録から補正を断る導線、縦向き390x844の鑑賞画面表示も確認。
- 人工的に生成した1536x1152の細密モザイク画像でテスト。ユーザーの実物パズル写真はGitHubに一切含めず、実機でのv1.2再確認待ち。
